# 蒸餾大腦思考方法論

## 定位

把經驗中的觀察、判斷與選擇理由寫出來，形成他人可以理解、試用及修正的知識。這裡的「大腦」與「蒸餾」是教學比喻，不是讀取神經訊號，也不是機器學習中的模型壓縮。

經驗回答「我做過什麼」；方法還要回答「何時這樣做、根據什麼、怎麼做、什麼情況不適用」。能說明不代表已證明有效，能寫成 SOP 也不代表完成傳承。

## 分析架構：情境 → 機制 → 證據 → 演進

1. **情境：** 誰要達成什麼？時間、資源、資訊與風險條件是什麼？
2. **機制：** 哪個因素可能影響結果？為何這個做法可能改變它？
3. **證據：** 哪些內容來自觀察？哪些只是推論？還缺哪些資料？
4. **演進：** 新資訊出現後，保留、修正或停止哪條規則？

四個 M 是可交互使用的視角，不是每個案例都必須支持的四個結論。

## M1｜主導限制配適

問：現在最妨礙目標的是什麼？所選做法是否真正作用於它？

拆解時分開「症狀、可能限制、選擇理由」。報價慢是症狀；資料缺漏、審核排隊或產能不明都可能是限制。需要看紀錄或追問，才能決定優先改善哪一項。

可留下的知識：觀察訊號 → 候選限制 → 下一步確認方式 → 對應行動。  
界線：主導限制可能隨時間改變；未排除替代原因前，應寫「可能」而非「確定」。

## M2｜複雜度配置

問：這個步驟為誰增加工作？保護了什麼價值？可以移到哪個環節？

刪除重複抄寫可能有幫助；保留一次關鍵規格確認也可能有必要。不要把工作轉給客戶或下一部門，就宣稱整體負擔降低。

可留下的知識：保留／移除／移轉哪個步驟，以及理由、責任與代價。  
界線：只看表單長度或按鍵數，無法判斷總負擔。

## M3｜能力累積

問：換一位同事遇到類似情境，是否能依留下的知識完成判斷？

保存檔案只是起點。還要能找到、讀懂、使用，並知道條件及例外。模板、清單與教材都可以承載知識；選擇哪種形式取決於使用情境。

可留下的知識：原則、步驟、案例、邊界與更新責任。  
界線：有 SOP 不等於組織已具備能力；應看他人能否使用。

## M4｜回饋有效性

問：回饋指出了哪個偏差？下一次改了什麼？如何知道修改有幫助？

收到退件通知只是訊號；辨認缺漏原因、修改追問，再觀察下一次交接，才形成修正循環。比較時也要看案件難度與其他條件是否改變。

可留下的知識：原判斷、回饋、修改、下次觀察項目。  
界線：有重試、有反思文字或有人點讚，不自動代表學習有效。

## 操作口訣：看 → 拆 → 留 → 傳 → 修

| 動作 | 實際工作 | 產物 |
|---|---|---|
| 看 | 說清楚情境與目標 | 一段經驗 |
| 拆 | 找觀察、理由及不確定處 | 思考拆解紀錄 |
| 留 | 提煉原則、流程、案例與邊界 | 一頁蒸餾卡 |
| 傳 | 讓另一個人解釋下一步 | 理解與使用回饋 |
| 修 | 按回饋改一處並記下理由 | 修訂紀錄 |

## 知識品質

- **清楚：** 區分觀察、推論與未知，能說出判斷理由。
- **可教：** 他人能用自己的話解釋原則與步驟。
- **可重用：** 明示適用情境、下一步與例外處理。

課堂達到這三項，只代表完成初步知識表達與傳遞，不等於已驗證企業效益。

## 與 AI to Agent 的關係

AI 可協助整理訪談、列出缺漏、提出替代解釋及改寫草稿；人負責確認來源、適用條件及決策責任。若後续要交給 Agent，須另寫輸入、輸出、允許行動、停止條件與驗收規則。一頁蒸餾卡可以作為準備材料，不自動等於可執行 VAC 或已安裝 Skill。

本方法不要求多代理架構，也不要求用 AI 完成課程。先讓人看懂方法，再決定是否自動化。

## 使用邊界

M1–M4 是本教材的候選分析機制；本包未包含可證明其普遍有效的研究。範例均為模擬教學資料，不能當作真實成效報告。對資料不足的問題，允許保留未知；對不符合情境的案例，允許不套用。
